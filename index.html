Professional direction

As I complete my Bachelor of Science in Computer Science at Southern New Hampshire University, I want my work to show that I can understand an existing system, explain its weaknesses and improve it with evidence. My interests connect secure software engineering and reverse engineering with networking, infrastructure, cloud computing and systems administration. My experience as a webmaster has reinforced my interest in work that combines software, troubleshooting and the systems supporting an organization.

The program has helped me move beyond asking whether a program runs. I now ask how its responsibilities are organized, what assumptions its inputs depend on, how its data structures affect performance, and what happens when an operation fails. Coursework in testing and secure coding helped me recognize that reliability and security depend on decisions made throughout development. My next professional steps are to deepen my technical experience and pursue security and cloud certifications when they support the roles I choose.

Collaboration and communication

My capstone was an individual development project, but the review process gave me a concrete way to practice responding to another person’s technical expectations. My instructor recognized the design and algorithm choices and asked for stronger objective tests, specific complexity statements and clearer links to course outcomes. I used that feedback to organize additional checks for failed authentication, invalid input, searching, ranking, undo and index consistency. The feedback changed what evidence I prepared, rather than simply changing the wording of a conclusion.

This review cycle supports Outcome One through the use of feedback, shared expectations and documentation that helps another person evaluate a decision. I do not equate it with leading a development team. It demonstrates how I can make individual work understandable and responsive to review. For Outcome Two, I use a code review video, written narratives, readable source files and labeled visualizations to explain the same work at different levels of detail. The portfolio introduces the problem and results before asking a reader to inspect the implementation.

Algorithms and engineering judgment

The artifact began as a client management program recovered in CS 410 Software Reverse Engineering. It stored five clients in global variables and located records through repeated conditions. The software design enhancement separated authentication, validation, logging and client management. That made responsibilities easier to reason about and created a foundation for later changes.

The algorithms enhancement made data structure selection an explicit design decision. An unordered map provides average constant time lookup by integer identifier, while an ordered name index supports exact and prefix searches. Sortable vectors, a bounded priority queue and an undo stack address different operations. These choices also introduce costs: the name index must stay synchronized, sortable views copy records, and undo history stores previous states. Outcome Three is demonstrated through those trade-offs and the additional regression checks, not through an unsupported claim that every operation became faster.

Outcome Four is demonstrated by extending the same artifact into a persistent Windows application built with Visual Studio 2022, C++17, WinSQLite and GDI+. AURELIA Wealth Studio connects client profiles, accounts, holdings, transactions, financial goals and advisor tasks. The final demonstration contains 25 fictional clients. Dashboard values and PDF and Excel reports derive from stored records. I kept the three enhancement stages distinct so the reader can see how software design, algorithms and relational persistence contribute different capabilities.

Security and verification

Outcome Five is reflected in input validation, limited authentication attempts, prepared statements, transactions, foreign keys, backups and audit history. The original embedded password is retained only in the clearly identified historical source. The enhanced versions use externally configured demonstration credentials. Those controls improve the demonstration, but they do not make it a production financial system. The SQLite file is unencrypted, authentication is basic, and production identity management and data protection remain future work.

Testing helped me distinguish an implementation claim from demonstrated behavior. Final console checks covered successful login, three rejected authentication attempts and invalid menu input for each earlier enhancement. Eleven additional algorithm scenarios checked identifiers, prefix searches, duplicate names, ranking, undo, index rebuilding, sorting, filtering and aggregate values. Earlier database workflow and UI validation recorded 111 and 298 passing assertions respectively. The final database demonstration also produced 26 PDFs and 26 workbooks whose 52 native Excel charts were checked against their worksheet data.

These results are useful within their scope. Functional checks are not performance benchmarks, a passing build is not proof of every feature, and the report checks do not establish investment suitability. The portfolio records those limits. It also separates dated public market observations from the fictional prices used in portfolio calculations.
